---
name: rt-exposure-review
description: Separate exposed-resource signals from catch-all pages, public identifiers, and unsupported secret claims.
budget: 500
---
Work within the active engagement. Plan the resource and test context with security_coverage. Preserve exact tool receipts before summarizing.

Collect a normal response, the suspected resource, and an appropriate control through existing scoped tools. Use compare_evidence to inspect redirects, content type, body equality, cache indicators, and status. A distinct HTTP 200 resource only establishes that a resource was returned.

Check alternative explanations: catch-all routing, authentication pages, examples, redacted values, public client identifiers, stale archives, and deliberate test data. Marker words are clues, not proof that data is harmless. Scanner severity and model confidence are not validation.

For suspected credentials, distinguish a secret-shaped string, a publicly intended identifier, and demonstrated privilege. Do not submit discovered credentials to a provider merely to increase confidence; the engagement's existing credential-use controls apply. If use is unavailable, report validity and impact as unverified.

Repeat the observation and record a separate control addressing the leading alternative explanation. Use review_finding before promotion. State exactly what was exposed and what remains unknown; raw evidence may contain sensitive data, so quote only the relevant portion in reports.
